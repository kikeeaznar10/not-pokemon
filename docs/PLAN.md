## How to use this plan

Work through the milestones in order, one at a time, each in its own fresh Claude Code session. Every milestone is self-contained: it says what must already exist, exactly what to build, which files to touch, and how to prove it works.

**Rules for every session (human or Claude Code)**

1. Before writing any code, read `CLAUDE.md`, `docs/PLAN.md` (this document, exported to Markdown) and `docs/PROGRESS.md` in the repo.
2. Work on exactly one milestone. Do not start the next one, even if there is time left.
3. Create a branch named `m<number>-<short-name>` (for example `m4-dialogue`) and open a PR into `main` when done.
4. Only change files listed in the milestone, plus tests. If you must touch another file, explain why in the PR description.
5. Never hard-code game content (creature names, numbers, dialogue, prices) in TypeScript. Content lives in `public/data/*.json` and `src/i18n/es.json`. Code reads it.
6. If the plan is unclear or wrong, stop, write the question in `docs/PROGRESS.md` under "Open questions", and do the rest of the milestone with the safest assumption. Never silently invent rules.
7. When finished, tick the milestone's checklist in `docs/PROGRESS.md` and add a 3–5 line summary: what was built, any deviation, anything the next session must know.

**Definition of done (applies to every milestone)**

- [ ] `npm run lint`, `npm run typecheck`, `npm test` and `npm run build` all pass with zero errors.
- [ ] Every item in the milestone's "Done when" checklist was checked by hand in the browser (`npm run dev`).
- [ ] No `console.log` left except through the `log()` helper in `src/core/log.ts`.
- [ ] No new hard-coded content; no Spanish text inside `.ts` files.
- [ ] `docs/PROGRESS.md` updated; PR opened.

**Milestone template.** Every milestone below uses the same headings: *Goal*, *Needs* (milestones that must be merged first), *Tasks* (numbered, in order), *Files*, *Done when* (a checklist a tester can follow without reading code).

## Game summary and locked decisions

Flexymon is a browser game (desktop and mobile) in the style of the Game Boy Color Pokémon games, set in a cartoon version of the Valencia region and themed around ahora (now Flexygo). There is no story and no ending: the player wanders, meets wild flexymon and enemy NPCs, fights them in turn-based battles, collects flexymon, earns euros and buys items.

These decisions are final. Change them only by editing this table, never in code.

| Area | Decision |
| --- | --- |
| Builders | Claude Code, in separate unrelated sessions. Each milestone must work from a cold start. |
| Art and sound | Placeholders generated by a script in M0; real assets swapped in later by replacing files at the same paths. |
| Language | Spanish only. All text in `src/i18n/es.json`, never in code. |
| Creature name | *flexymon* (singular and plural). Never the word "Pokémon" or any Nintendo asset in the game. |
| Goal | None. Free wandering. No final boss, no credits. |
| Starter | Every new game starts with one flexymon, *Portátil*, handed over in the office intro. |
| Catching | 100% on victory against a wild flexymon. The player chooses *Llevármelo* or *Dejarlo*. A catch item may be required later (hook reserved, see Rules). |
| Stats | HP, Ataque, Defensa, Velocidad. No types, no levels, no XP. |
| Attacks | At most 3 per flexymon. Effects: damage, heal, buff, debuff. Each attack has accuracy; no critical hits. |
| Merging | Catching a species you already own merges it: a random stat gains +10% of its *base* value, never above 2× base. |
| Team | Starts at 2 slots. A stackable item adds +1 slot each, up to 6. Extras go to the storage box at the office. |
| Turn actions | Atacar, Cambiar, Objeto, Huir. Cambiar and Objeto use the turn. Huir works 100% vs wild, is disabled vs NPCs. |
| Enemy NPCs | Wander inside a set area. Line of sight 4 tiles: they walk up, speak, then fight. |
| Rematches | After you beat an NPC it stays inactive until you are more than 6 tiles away, then it can challenge you again. When you lose, every NPC resets to fightable. |
| Rewards | Beating an NPC pays a random whole number of euros between its `min` and `max`. |
| Losing | You wake up at the office with half your euros (rounded down) and a fully healed team. |
| Healing | Free at the office. Bars sell healing items. |
| Shops | One per town, items and prices in config. |
| Murcia access | A white Audi A3 parked at the office drives you there at dangerous speed. You need one of several allowed pairs of items. Items are not consumed. The car in Murcia brings you back with no requirement. |
| Encounters | Wild-grass tiles (grass, sand, vineyard variants) and "urban crowd" zones in the city, each with its own rate and flexymon list in config. |
| Intro | Title screen shows the pixel office. New game: enter a name, walk into the office, a coworker hands you Portátil. Secret names grant bonus starting items. |
| Saving | Auto-save to browser localStorage, one slot. No backend, no accounts. |
| Controls | Desktop: arrows/WASD move, Z = A, X = B, Enter = Start, M = minimap. Mobile: on-screen D-pad, A, B, Start; landscape only. No gamepad. |
| Minimap | On both desktop and mobile; toggled with M or a touch button. |
| Hosting | Static site (any static host), shared by internal link. |
| Debug | A debug menu (dev builds only) to teleport, start any battle, give items and reload config. |

## Tech stack, repo structure and conventions

The game is a TypeScript + Vite + Phaser static site, maps are made in Tiled, and all content is validated JSON.

| Tool | Use | Notes |
| --- | --- | --- |
| Node.js LTS + npm | Build tooling | Version written in `.nvmrc` in M0. |
| TypeScript (strict) | All game code | `strict: true`, no `any` without a comment explaining why. |
| Vite | Dev server and build | Output in `dist/`, fully static. |
| Phaser (latest stable, exact version pinned) | Engine | M0 installs the latest stable release and pins it with no `^`. |
| Zod | Config validation | Every JSON file has a schema in `src/data/schemas/`. |
| Vitest | Unit tests | Required for everything in `src/logic/`. |
| ESLint + Prettier | Style | Run on every commit via `npm run lint`. |
| Tiled (desktop app) | Map editor | Maps saved as `.tmj` (Tiled JSON), tilesets embedded. |

**Screen.** Base resolution 512 × 288 pixels (16 × 9 tiles of 32 px). Phaser scale mode `FIT`, `pixelArt: true`, `roundPixels: true`. Everything is placed in tile or pixel units of this base, never in screen pixels.

**Folder structure** (M0 creates every folder, even empty ones, with a `README.md` saying what goes there):

```
    assets/ui/               boxes, buttons, cursor, fonts
    assets/audio/sfx/        attack and UI sounds (OGG + MP3)
    assets/audio/music/      one loop per region
    maps/                    Tiled maps (.tmj), one per zone
    data/                    game content JSON (see Config spec)

    main.ts                  creates the Phaser game

    scenes/                  Boot, Preload, Title, Intro, Overworld, Battle, Menu, Shop, Car, Debug
    ui/                      DialogBox, Menu, HpBar, TouchControls, Minimap

    i18n/es.json             every visible string

```

**Conventions**

- Files `kebab-case.ts`, classes `PascalCase`, functions and variables `camelCase`, content ids `snake_case` (for example `portatil`, `bar_pacos`).
- `src/logic/` never imports Phaser. It receives plain data and returns plain data, so it can be tested without a browser.
- Randomness only through `src/core/rng.ts` (a seedable generator), so tests can fix the seed.
- Text: `t('battle.wild_appeared', { name })` reads `es.json` and fills `{name}`. A missing key shows `⟦battle.wild_appeared⟧` on screen and logs a warning.
- Scenes talk through `src/core/events.ts` (a typed event bus), not by reaching into each other.
- Commits in English, imperative: "Add dialogue box".

## Config specification

All game content lives in nine JSON files in `public/data/`; adding content never needs a code change. On startup the Boot scene loads every file, checks it against its zod schema, then checks cross-references (every id used exists). Any error stops the game on a red screen listing file, JSON path and message, for example `npcs.json › [3].team[0] › unknown flexymon "teclado"`.

All paths are relative to `public/`. All visible text is written directly in Spanish in these files (content text is not duplicated in `es.json`; `es.json` is only for UI text like menu labels).

## Game rules specification

Every rule below is implemented as a pure function in `src/logic/` with unit tests that use the exact examples given here. All tunable numbers live in `src/logic/constants.ts`.

### Owned flexymon

Each flexymon the player owns is an *instance*: `{ uid, speciesId, bonus: { hp, attack, defense, speed }, currentHp }`. `uid` is a unique string made by `rng.id()`. A stat's value is `base + bonus`. Max HP is `base.hp + bonus.hp`. A flexymon with `currentHp = 0` is *debilitado* (fainted) and cannot fight until healed or revived.

### Battle flow

1. Battle starts: show the opponent, then send out the first non-fainted flexymon in the player's team.
2. Each round the player picks one action: **Atacar** (pick one of up to 3 attacks), **Cambiar** (pick a non-fainted team member that is not active), **Objeto** (pick an item usable in battle, then its target), **Huir** (wild only).
3. The opponent picks an attack (AI below).
4. Actions resolve in this order: Huir, then Cambiar, then Objeto, then attacks. If both attack, the higher *effective* speed goes first; a tie is decided by `rng.chance(50)`.
5. If a flexymon faints, the rest of that round is skipped for it.
6. End of round: every active buff/debuff loses 1 turn; at 0 it is removed.
7. Player's active faints: if another team member is alive, the player must pick it (this does not cost a turn). If none is alive, the player loses.
8. Opponent faints: wild → victory. NPC → its next flexymon comes in automatically; if none left → victory.

### Hit and damage

An attack hits if `rng.int(1, 100) <= accuracy`; otherwise show "¡Ha fallado!" and nothing else happens. A damage attack deals:

```latex
\text{damage} = \max\left(1,\ \left\lfloor \text{power} \times \frac{\text{Atk}_{eff}}{\text{Def}_{eff}} \times 0.3 \times r \right\rfloor\right),\quad r \in [0.85,\ 1.00]
```

`0.3` is `DAMAGE_SCALE` in constants. `r` is `rng.float(0.85, 1.0)`. Example for a unit test: power 40, Atk 12, Def 10, r = 1.0 → floor(14.4) = 14. With r = 0.85 → floor(12.24) = 12. HP never goes below 0.

Heal attacks restore `floor(maxHp × percent / 100)`, never above max HP.

### Buffs and debuffs

An effective stat is `stat × (100 + sum of buff percents − sum of debuff percents) / 100`, then clamped between 25% and 250% of the stat, then floored (minimum 1). Using the same attack or item again on the same flexymon replaces its old modifier (turns reset) instead of stacking. Modifiers are removed when a flexymon switches out or the battle ends.

Example: Defense 10 with one −25% debuff → 7.

### Opponent AI

- **Wild:** picks a random attack (equal chance).
- **NPC enemy:** if its HP is below 25% of max and it has a heal attack, it heals. Otherwise it uses the damage attack with the highest `power × accuracy`. If it has no damage attack, a random one. NPCs never use items or switch.

### Catching and merging

After beating a wild flexymon, show "¿Te llevas a {name}?" with *Llevármelo* / *Dejarlo*. `canCatch()` always returns true for now; it is the hook for a future catch item.

If taken and the player does **not** own that species: a new instance with zero bonus and full HP goes into the team if there is a free slot, else into the storage box (show a message saying so).

If the player **does** own that species, it merges into the existing instance (team first, then storage, first match):

1. Collect stats whose `bonus` is below `base` (that is, value below 2 × base).
2. If none: show "{name} ya está al máximo" and stop.
3. Pick one with `rng.pick`. Add `max(1, round(base × 0.10))`, but never past `bonus = base`.
4. If the stat is HP, raise `currentHp` by the same amount.
5. Show "¡{name} se ha fusionado! {stat} +{n}".

Example: base attack 12 → +1 each merge (round(1.2) = 1); maximum attack 24 after 12 merges.

### Team and storage

Team size starts at `start.json › teamSlots` (2). Each *Regleta* used adds 1, max 6 (the item cannot be used at 6). The team can never be empty: the last flexymon cannot be moved to storage. Storage has no limit and is opened by the `storage` NPC in the office.

### Wild encounters

Checked once each time the player *finishes* a step. An encounter is possible if the tile is inside an encounter rectangle of the current map and either the rectangle's mode is `all` (urban crowd) or the tile has the Tiled property `encounter = true` (grass, sand, vineyard). Then roll `rng.chance(rate)`; on success pick a species by weight. After any battle or map change there are 3 safe steps with no rolls.

### Enemy NPCs

States: `ready`, `cooldown`. A `ready` NPC sees the player if the player stands in a straight line in front of it, at most `sight` tiles away, with no blocking tile or NPC between them. Then: player input locks, a "!" bubble shows for 600 ms, the NPC walks until adjacent, says `dialogue`, and the battle starts. While walking, NPCs never trigger other NPCs.

Players can also talk to a `ready` NPC (face it and press A) to start the same sequence.

After the player wins: euros `+= rng.int(min, max)`, the NPC says `defeatDialogue`, and its state becomes `cooldown`. A `cooldown` NPC talks with `defeatDialogue` only. It returns to `ready` when the player is more than 6 tiles away (Manhattan distance: |dx| + |dy| > 6) or on another map. The 6 is `NPC_COOLDOWN_DISTANCE`.

### Losing

When all team members are fainted: fade to black, then euros = floor(euros / 2), all team and storage flexymon fully healed, every enemy NPC set to `ready`, player placed at `start.json › respawn`, message "Te has despertado en la oficina...".

### Euros and shops

Euros are whole numbers from 0 to 999 999. Buying checks money first; selling gives floor(price / 2). Key items and `price: null` items cannot be sold.

### Saving

Auto-save to `localStorage` key `flexymon.save.v1` after every map change, battle, shop visit and menu close. Format:

```json
{ "version": 1, "savedAt": "2026-11-04T21:00:00Z",
  "player": { "name": "Rogelio", "map": "valencia", "x": 40, "y": 22, "facing": "down" },
  "euros": 340, "teamSlots": 2, "team": [ { "uid": "a1", "speciesId": "portatil", "bonus": { "hp": 4, "attack": 0, "defense": 1, "speed": 0 }, "currentHp": 31 } ],
  "storage": [], "items": { "cafe": 2 }, "npcs": { "becario_rio": "cooldown" } }
```

If the saved JSON cannot be read or fails its schema, copy it to `flexymon.save.broken`, and the title screen offers only *Nueva partida*. Save ids that no longer exist in config (a removed flexymon) are dropped with a warning instead of crashing.

## Milestones

Sixteen milestones, M0 to M15, each one session-sized and mergeable on its own. After M7 the game is playable end to end with wild battles; after M11 it is a complete game on desktop; M12–M15 add mobile, Murcia, the real world and polish.

### M0 — Project skeleton and placeholders

**Goal:** an empty Phaser game that builds, lints, tests and shows a coloured screen with "Flexymon".

**Needs:** nothing.

**Tasks**

1. `npm create vite@latest` with the vanilla TypeScript template. Install Phaser (exact latest stable), zod, vitest, eslint, prettier, tsx.
2. Add scripts: `dev`, `build`, `preview`, `lint`, `typecheck` (`tsc --noEmit`), `test` (`vitest run`), `placeholders` (`tsx tools/make-placeholders.ts`).
3. Create the full folder structure from the Tech stack section, each folder with a one-line `README.md`.
4. `src/config/game.ts`: 512 × 288, `pixelArt: true`, scale `FIT` + `CENTER_BOTH`, black background. Scenes `Boot` and `Preload` only.
5. `src/core/log.ts` (`log`, `warn`, `error`, silent in production builds), `src/core/rng.ts` (seedable: `int`, `float`, `chance`, `pick`, `weighted`, `id`), `src/core/events.ts` (typed emitter).
6. `src/i18n/index.ts` with `t(key, vars)` reading `es.json` (rules in Conventions). Add `"app.title": "Flexymon"`.

## Content guide

Adding content is editing JSON and Tiled maps only; after any change, run `npm run placeholders`, then `npm run dev` and fix anything the red error screen reports.

**Add a flexymon**

1. Add its attacks to `attacks.json` first (new ids, or reuse existing ones).
2. Add an entry to `flexymon.json` with a new `snake_case` id, the Spanish name, sprite and cry paths, four stats and 1–3 attack ids.
3. Run `npm run placeholders` to get placeholder images and sound, or drop real files at those paths (front/back 64 × 64 PNG, icon 16 × 16 PNG, OGG + MP3 with the same name).
4. Make it appear: add `{ "id": "...", "weight": n }` to an encounter group in `zones.json`, or to an enemy NPC's `team`.
5. Balance guide: total stats between 60 and 100 for early areas, 100–140 for Murcia.

**Add an NPC**

1. Open the map in Tiled, hover the tile where it should stand, and note the x/y shown at the bottom.
2. Add an entry to `npcs.json` with that `map` and `spawn`. For a wanderer, draw the rectangle mentally (or as a temporary Tiled rectangle) and copy its x, y, width and height in tiles.
3. Write the dialogue as a list of short Spanish strings, one per text box.
4. For enemies add `sight`, `team`, `reward` and `defeatDialogue`.

**Add an item:** an entry in `items.json`, a sprite (16 × 16 PNG), and add its id to a shop in `shops.json` or to an NPC gift.

**Add or edit a map (Tiled)**

1. New map: orthogonal, 32 × 32 px tiles, "Tile layer format: CSV", save as `public/maps/<zone_id>.tmj` with tilesets embedded.
2. Layers, top to bottom, with these exact names: `spawns` (objects), `encounters` (objects), `warps` (objects), `above`, `collision`, `deco`, `ground`. The `collision` layer is hidden in game; any tile with property `solid = true` blocks.
3. Grass, sand and vineyard tiles that start encounters get the tile property `encounter = true` in the tileset.
4. Draw encounter rectangles in `encounters` with properties `group` and `mode` (`tiles` or `all`), then add the group to `zones.json`.
5. Draw warps in `warps` with `toMap`, `toX`, `toY`, `toFacing`, `trigger`. Every door needs a matching warp back on the other map.
6. Add the zone to `zones.json` with its music and encounter groups.
