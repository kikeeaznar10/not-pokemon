# maps — Tiled maps (.tmj, CSV layers, embedded tilesets), one per zone

Layer names: see docs/PLAN.md › Content guide. Rules the game applies (`src/data/tiled.ts`):

- Tile layers `ground`, `deco`, `above` (drawn over the player), `collision` (never drawn).
- A cell blocks if ANY tile layer has a tile whose tileset tile has the bool property `solid = true`; the map edge
  also blocks. `encounter = true` marks encounter tiles (tall grass, sand, vineyard).
- Object layer `warps` (M4): rectangles with `toMap` (zone id), `toX` / `toY` (int; leave one out to keep the
  player's column / row, as edge warps do), `toFacing` (optional: keep facing) and `trigger` (`step`: doors and
  edges, fires when a step ends inside it; `action`: press A facing it, for the car). A step warp may sit one tile
  outside the map; those off-map tiles become walkable, so walking off the edge enters it. Every door needs a
  matching warp back. Load checks: the target zone exists and every tile the warp can land on is walkable.
- Object layer `encounters` (M7): rectangles with string properties `group` (a key of the zone's `encounters` in
  `zones.json`) and `mode` (`tiles`: only tiles with `encounter = true` roll; `all`: every tile, for urban crowds).
  The first rectangle containing the tile wins. Load checks: a group missing from zones.json is an error; a group in
  zones.json that no rectangle uses is only a warning (logged at boot).
- Object layer `spawns`: point objects; the one named `default` is the zone's spawn point. Its tile is
  `floor(x / 32), floor(y / 32)`, the same numbers Tiled shows in its status bar.
- Tileset image paths are relative to the map file (e.g. `../assets/tilesets/test.png`).
